# XIAOJUESHI 项目约定

## 目标与范围

面向中文开发者的个人品牌与内容工作台。管理员可在桌面和手机浏览器记录文章、随笔和笔记，组织知识库，并主动发布公开内容。读者无需注册。

第一版不包含评论、点赞、付费内容、邮件订阅、定时发布、离线编辑、多设备自动冲突合并、双向链接和块级引用。

新内容默认私密；类型、可见性、版本分别建模。保存编辑稿不能影响已发布版本；撤回后公开接口、搜索和附件源站访问须同步停止。已被下载的内容无法收回。

## 技术方向

- Nuxt、Vue、TypeScript；前台 SSR，后台按需加载。
- mise 管理 Node.js，pnpm 管理依赖；具体版本实施时核实并锁定。
- 数据库存储 Markdown、元数据、编辑稿、发布版本及历史版本。
- 前后台共用 remark/rehype 渲染规则；编辑器需通过中文输入、移动软键盘与长文验证后选定。
- 支持代码高亮、表格、任务列表、公式、Mermaid、脚注、提示块和图片上传。
- 正文不执行任意 JavaScript 或任意 Vue 组件；外部演示通过链接或受控嵌入呈现。
- 首选 Workers、D1、R2；隔离平台访问，验证普通服务器迁移路径。
- GitHub Actions 执行代码检查、测试、构建和部署；内容发布不依赖构建。
- 基础设施预算每月人民币 50 元以内，优先免费额度；开通收费资源、外部部署和 Git 推送需要明确授权。

## 核心功能

- 单管理员登录，无公开注册；会话与接口鉴权。
- Markdown 编辑、预览、自动保存、失败提示、未完成内容恢复。
- 保存与发布分离，历史版本可恢复；并发修改须检测冲突，避免静默覆盖。
- 单层分类、多个标签；知识库目录可嵌套并引用现有内容。
- 公开知识库仅展示允许公开的内容，不能连带公开私人笔记。
- 后台搜索全部内容，前台仅搜索公开发布版本；中文关键词、标题优先、分类筛选。
- Markdown 批量导入；完整导出 Markdown、JSON 元数据及原始附件，恢复内部链接。
- RSS、基本 SEO、公开文章列表、详情、知识库、项目及关于页面。

## 首页与响应式

根据用户视觉反馈，采用纯白底、黑色文字与中性灰，取消暖米色、橄榄灰和橙色。品牌使用完整 XIAOJUESHI 纯文字字标，不使用独立 x 图形；全站采用无衬线字体，社交账号保留 xiaojueshi。首页主标语为“永远相信美好的事情即将发生”，其他界面文案直接、简洁，避免文艺化表达。

首页顺序：个人介绍、精选文章、最近记录、代表项目、社交链接。导航为文章、知识库、项目、关于。中文介绍文案为待审核草案，不虚构经历或项目。

桌面品牌区使用不含字母的黑白线框立方体，轻微响应指针，不阻塞正文与导航；使用 CSS 3D，无 WebGL 依赖。手机端隐藏装饰以优先呈现标语和内容，尊重减少动态效果偏好。

移动端单栏，介绍后尽快出现内容入口；正文保持舒适行宽，代码和表格在各自容器内滚动。目录折叠，导航可触达。后台移动端全屏编辑、切换预览，保存状态持续可见；考虑软键盘、安全区域、触摸操作和长标题。

## 自动化测试与视觉验收

用户明确要求自动化测试，以及开发过程中打开实际网页、查看页面截图、检查美观与符合程度。实现后必须执行，不能仅交付测试代码或仅凭源码判断效果。

### 测试分层

- 单元测试：公开规则、版本切换、Markdown 扩展与安全过滤、搜索过滤、链接转换等独立规则。
- 集成测试：数据库读写、鉴权、附件权限、自动保存冲突、发布撤回、历史恢复和导入导出。
- 浏览器端到端测试：登录 → 写作 → 自动保存 → 刷新恢复 → 预览 → 发布 → 公开阅读与搜索 → 撤回；覆盖完整备份恢复。
- 私密性回归：未登录时直接请求正文、搜索、知识库目录及附件接口，均不能泄露私密数据；不得只检查界面隐藏。
- CI 执行类型检查、适用测试及生产构建；平台适配需要实际目标运行环境验证。

### 视觉与交互检查

- 使用实际浏览器检查桌面约 1440px、平板约 768px、手机约 390px，以及窄屏约 320px。
- 检查首页、列表、详情、知识库、登录、后台列表和编辑器；包含空状态、长标题、长代码、表格、公式、Mermaid、错误与保存状态。
- 开发阶段持续截图并实际查看，发现问题后修正再截图；不能以截图生成成功代替视觉验收。
- 检查层级、留白、对齐、字重、中文可读性、触摸目标、横向溢出、图片布局稳定性和加载状态。
- 检查键盘访问、焦点可见性、减少动态效果和无 WebGL 降级；验证导航与内容不依赖动效。
- 截图回归使用确定性数据，等待字体与内容加载，关闭非必要动画；基线须先人工查看，不得无条件更新基线掩盖问题。
- 保留截图与测试报告，记录已检查的尺寸、页面、结果及尚未验证的限制。移动浏览器模拟不能代替真实手机中文输入和软键盘验证。

## 实施顺序

1. 建立应用、数据边界与基本响应式品牌样式。
2. 完成登录、编辑、保存、预览、发布、阅读、搜索、备份恢复的纵向闭环及对应测试。
3. 完善知识库、分类标签、版本管理与内容迁移。
4. 优化首页视觉与局部动效，完成多尺寸视觉检查。
5. 核实免费额度、目标网络访问与迁移部署；明确授权后连接外部资源和发布。
